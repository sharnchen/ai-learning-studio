三、雙 CLIP 文字條件如何運作？

Tokenizer 會把字串拆分成 tokens，文字編碼器將其轉為 embeddings，供 U-Net 在各個去噪步驟參考。SDXL 的 prompt 與 prompt_2 分別對應兩組編碼器；negative_prompt 和 negative_prompt_2 則提供負向條件。

每組 CLIP 常見最大序列長度為 77 個位置（包含特殊 token），所以原 Notebook 以 75 個有效 tokens 為保守上限。這不表示兩組編碼器可以不加限制地拼接成一段長 Prompt；應依優先順序將「主體、全身、服裝、鞋款」放前面，次要細節依 token 預算加入。

實作提醒： 使用實際 tokenizer 計數；不要只數英文單字，也不要依賴模型靜默截斷。鞋款與服裝矛盾（例如運動鞋卻在 Negative Prompt 排除 sneakers）會削弱條件一致性。

四、Latent Diffusion：為何能從雜訊畫出圖片？

SDXL 主要在壓縮過的潛在空間去噪。以 832×1216 圖片為例，常見 latent 大約是 4×104×152，空間維度約是 RGB 的八分之一。訓練時 VAE Encoder 將圖片映射至 latent，推論完成後 VAE Decoder 將 latent 還原為 RGB。

4.1 前向加噪（訓練）

xt = √ᾱt x0 + √(1 − ᾱt) ε ，ε ∼ N(0,I)

x₀ 是乾淨 latent；ε 是高斯雜訊；ᾱₜ 是累積訊號保留係數。這是教學上常見的加噪表達式，並非直接展示模型內部每一個計算細節。

4.2 反向去噪（推論）

輸入 Prompt 和 Seed 後，程式產生初始隨機 latent。U-Net 在每個時間步估計雜訊，Scheduler 根據演算法更新 latent；反覆 Steps 次後由 VAE 解碼。Steps 不是圖片被平均修復成 1/35 的過程，而是數值求解的迭代次數。

五、Steps、CFG、Seed 與張數

5.1 CFG（Classifier-Free Guidance）

ε̂ = εuncond + w ( εcond − εuncond )

其中 w 是 CFG Scale；εcond 是正向條件噪聲預測，εuncond 表示無條件或負向條件的預測。CFG 提高通常使 Prompt 的影響較強，但過高可能導致膚色、光影、細節不自然。

七、實驗紀錄與結論

每次推論建議保留 PNG、參數 JSON、耗時 CSV 和評分結果。Notebook 已提供實驗生成、結果下載、CSV 與 ZIP 匯出。報告須記錄假設、自變量、控制變量、各張圖片的觀察、運算時間、結論及不確定性。

常見問題：半身圖可比較 2:3 與 9:16 的取景；鞋子錯誤時檢查正負 Prompt 是否互斥；腳趾或臉部變形時，單純把 Steps 加到 100 不能保證修復，應進一步使用局部重繪。若出現 CUDA OOM，調低尺寸、逐張生成或開啟 CPU Offload。
